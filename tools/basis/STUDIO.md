# BAZIS Studio — концепция и дорожная карта

## Суть

**Studio — наш собственный «мини-БАЗИС» в браузере.** Пользователь получает
изделие из ТЗ (или создаёт с нуля), полностью настраивает его под свой вкус —
габариты, секции, материалы, фурнитуру, отдельные детали — руками или словами
через ИИ-чат, и в конце получает **производственный `.b3d`, который учитывает
все изменения**. Десктопный БАЗИС и лицензия для этого не нужны: платная
операция только одна — финальная сборка `.b3d` через облако (~10₽).

```
ТЗ (текст/фото/чертёж) ──► ParamSpec ──► [ STUDIO: настройка до вкуса ] ──► .b3d для БАЗИС
                                          ▲ живое 3D + чертёж + смета          (все правки учтены)
                                          ▲ проверки после каждой правки
                                          ▲ правки руками и ИИ-чатом
```

## Принципы (не нарушать)

1. **Один источник правды — ParamSpec** (+ слой точечных оверрайдов). Координаты
   панелей всегда считает детерминированный генератор, не LLM и не JS.
2. **Каждая правка — полный прогон проверок** (схема / встык / геометрия /
   .cfrn / присадки). Что видишь на экране = что уйдёт в производство.
3. **Платное — только осознанно.** Всё редактирование, чертежи, смета — бесплатно
   и локально; «Собрать .b3d» — по явному клику и только при зелёных проверках.
4. **Материалы — из производственной базы** (5047 позиций, артикулы/цены), а не
   выдуманные: подбор позиций резолвером, точный выбор — пользователем.
5. **API БАЗИС не используется** нигде, кроме финальной конвертации
   .cfrn→.b3d (и то по явному запросу пользователя).

## Дорожная карта — Studio 2.0 (эпик AKD-114)

### Фаза A — точность правок (ядро конфигуратора)

- **A1. Выбор детали кликом в 3D**: подсветка панели, карточка детали
  (имя, габариты, толщина, материал, кромка, присадки), подсветка той же детали
  на чертеже. Основа для всех точечных правок.
- **A2. Слой оверрайдов**: точечные правки поверх генератора — переименовать,
  изменить размер/положение, удалить деталь, добавить произвольную панель.
  Хранится в спеке (`overrides[]`), переживает регенерацию; конфликт оверрайда
  с новой геометрией → warning, а не молчаливая поломка.
- **A3. Секции 2.0**: per-section параметры в UI — высоты ящиков, сторона петель
  двери, уровни полок, ниши (front_top/front_bottom), доля ширины колонок
  с визуальным превью; drag-границы колонок.
- **A4. Фурнитура из базы**: выбор конкретных ручек/петель/направляющих/опор
  из шорт-листов резолвера (они уже считаются), позиционирование ручек
  (центр/край/отступ), пересчёт присадок под выбранную фурнитуру; статус
  «все позиции подобраны» — бейджем.

### Фаза B — визуализация «как в салоне»

- **B1. Текстуры декоров**: процедурная имитация текстуры дерева от базового
  цвета (canvas → THREE.Texture, направление волокон по ориентации детали);
  если рядом лежит папка реальных jpg текстур (пути уже есть в базе,
  1520 позиций) — подхватывать их.
- **B2. Размерные линии в 3D**: габариты изделия, ниш и секций поверх модели
  (toggle), обновляются при правках.
- **B3. Разнесённый вид (exploded)**: слайдер «разнести» для проверки состава;
  печатается в лист согласования.
- **B4. Чертёж 2.0**: вид сверху, деталировка (панель → размеры с кромкой),
  экспорт PDF/печать; связь выбора детали 3D↔чертёж.

### Фаза C — производство и деньги

- **C1. Смета live**: стоимость материалов по площади деталей (цены базы —
  2304 позиции с cost), кромка по периметру, фурнитура поштучно; итог в шапке,
  обновляется при каждой правке. Разбивка по группам в панели BOM.
- **C2. Раскрой-превью**: простой bin-packing деталей по листам выбранной плиты
  (2800×2070 и т.п.) → число листов, остаток, стоимость точнее; локально,
  без платного Cutting API.
- **C3. Экспорт-центр**: история сборок .b3d (когда/что/сколько стоило),
  автооткрытие результата в БАЗИС-Просмотре (`D:\bazis\viewer.exe`),
  лист согласования PDF (delivery.py) — 3D-рендер + спека + смета, одним кликом.
- **C4. Резолв материалов до конца**: `facade_article` в material_refs,
  бейдж «материалы: N/M подобраны», клик по неподобранному → выбор из кандидатов.

### Фаза D — проекты и ИИ

- **D1. Каталог проектов**: открыть/создать/дублировать спеку прямо из Studio
  (список paramspecs/ + недавние), без перезапуска CLI.
- **D2. Версии**: именованные снапшоты спеки (v1, v2…), сравнение diff-ом,
  восстановление; undo переживает перезагрузку страницы.
- **D3. Чат 2.0**: создание изделия с нуля («сделай тумбу 600×450×550 с тремя
  ящиками»), вопросы о модели («какая высота ниши?», «сколько стоит?»),
  команды на фурнитуру («ручки скобы 192 по краям»).
- **D4. Импорт ТЗ в один клик**: drag&drop фото/эскиза/PDF в Studio →
  Vision-извлечение ParamSpec → сразу в редактор (нужен OPENAI_API_KEY).

### Приоритет реализации

**A1 → A4 → C1 → C3 → B1** — сначала точность правок и деньги (это делает
Studio полноценным конфигуратором «настроил → увидел цену → получил .b3d»),
затем красота. A2/A3 — по мере запроса реальных кейсов; D — фоном.

## Ограничения (честно)

- Цвета/текстуры показа — условные; фотореализм декоров = MatBase БАЗИС (AKD-87).
- 3D-меши фурнитуры (ручки-модели) — из каталогов БАЗИС не достать без
  десктопа (AKD-14); рисуем схематично, присадки — точные.
- Круглое/фигурное (round_table) в .cfrn пока габаритным боксом (AKD-42).
