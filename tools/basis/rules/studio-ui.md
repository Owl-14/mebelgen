# Studio UI: контракт визуальных правок без регрессий

Этот документ обязателен для любой задачи со словами «интерфейс», «визуал»,
«редизайн», «компоновка», «панель», «кнопка», «удобство» или «UX» в Studio.

## Базовое правило

Визуальная задача улучшает существующий Studio. Она не создаёт отдельный
макет продукта и не заменяет работающие части демонстрационными аналогами.

Источники истины:

- страница и связка с API — `src/studio.py::PAGE`;
- настоящий интерактивный 3D — `src/webviewer.py::SCENE_JS` / `MebelScene`;
- данные модели — реальный payload `build_payload`, а не fixture внутри JS.

## Утверждённая и неприкосновенная 3D-сцена

Пользователь отдельно утвердил текущий визуальный результат и физику
`MebelScene`. Для всех задач интерфейса 3D-сцена считается готовым продуктовым
ядром и используется как «чёрный ящик».

Без отдельной прямой просьбы пользователя запрещено менять:

- `src/webviewer.py`;
- геометрию, пропорции и расположение деталей;
- материалы, текстуры, свет, тени и фон самой Three.js-сцены;
- перспективную и ортографическую камеры и пять утверждённых ракурсов;
- OrbitControls: вращение, масштабирование и панорамирование;
- raycast, hover, выбор, подсветку и hit areas;
- Shift+drag, снап, магнит и координатные преобразования;
- анимации дверей и ящиков;
- визуализацию присадок, фурнитуры, размеров и осей;
- x-ray, isolate и exploded view;
- payload сцены и связь индексов mesh с реальными панелями.

Редизайн меняет только продуктовую оболочку вокруг `#view3d`: навигацию,
дерево, inspector, toolbars, статусы, режимы, производственные таблицы,
типографику, иконки и компоновку.

В Figma используется скриншот или живая фиксация настоящей сцены. Рисовать
альтернативную мебель, «улучшать» её стилизацию или подменять её декоративным
placeholder запрещено даже на концептуальном макете.

Гейт для любой UI-задачи:

```bash
git diff --exit-code <base> -- src/webviewer.py
```

Если `src/webviewer.py` имеет diff, визуальная задача не передаётся на review.

## Запрещено по умолчанию

- заменять Three.js-сцену статичным SVG, картинкой или декоративной 3D-имитацией;
- удалять, скрывать без доступной альтернативы или превращать в mock уже
  работающие функции;
- рисовать отдельную версию интерфейса на вымышленных данных и выдавать её за
  направление production Studio;
- менять геометрию, генераторы, ParamSpec, присадки, фурнитуру или экспорт ради
  визуальной задачи;
- подменять реальные API локальным состоянием прототипа;
- считать задачу готовой только по скриншоту.

Если продуктовая идея требует одного из этих действий, она выносится в
отдельное предложение и не реализуется без прямого согласования пользователя.

## Визуальный язык: профессиональный CAD, а не «нейросайт»

Akeda Studio — плотный desktop CAD/CAM-инструмент. Главный объект экрана —
настоящая 3D-модель, а интерфейс выглядит как спокойный точный прибор.

Обязательные принципы:

- viewport получает максимум места; большой product topbar не добавляется;
- панели отделяются линиями и тоном поверхности, а не стопками карточек;
- постоянные панели не используют blur, glow и тяжёлые плавающие тени;
- canvas имеет ровный нейтральный фон без декоративных CSS-градиентов;
- базовые радиусы 4–6 px, 8 px допустимы для меню и модальных окон;
- основной текст 13 px, подписи 11–12 px, числовые значения используют
  `font-variant-numeric: tabular-nums`;
- заголовки групп пишутся sentence case, а не сплошным капсом;
- один акцентный цвет обозначает выбор, активный инструмент, focus и главное
  действие; success/warning/danger используются только для реального состояния;
- редкие инженерные действия имеют текст; icon-only допустим только для
  известных команд с tooltip и shortcut;
- emoji и случайные Unicode-значки не используются как финальная система иконок;
- motion объясняет состояние: 100–160 мс для hover/popover, 180–220 мс для
  toast; без bounce, hover-lift, parallax и декоративных page-load анимаций;
- обязательно поддерживается `prefers-reduced-motion`.

Жёстко запрещены:

- shadcn-подобные белые карточки на сером фоне как основной язык продукта;
- KPI-карточки для деталей, присадок, площади и стоимости;
- glassmorphism, `backdrop-filter`, glow и декоративные цветные пятна;
- огромные скругления, pills повсюду и градиентные primary-кнопки;
- AI-sparkle и «магические» эффекты ради модности;
- смешивание emoji, Lucide, Material и случайных SVG в одном интерфейсе;
- Tailwind, shadcn, MUI, Bootstrap, Framer Motion или новый frontend framework
  только ради редизайна;
- runtime CDN для шрифтов, иконок или UI-библиотек.

Перед кодом нового визуального направления нужно:

1. Собрать в Figma токены и компоненты.
2. Нарисовать один экран настоящего Studio минимум в состояниях: default,
   выбранная деталь, открытые фасады, exploded, чертёж и раскрой.
3. Проверить, что на макете присутствуют все реальные функции baseline.
4. Получить визуальное согласование.
5. Реализовать один вертикальный срез и проверить его в живом Studio.

## Функциональный baseline, который обязан сохраниться

### 3D и выбор

- OrbitControls: вращение, масштабирование и панорамирование;
- пять ракурсов: аксон, перспектива, сверху, спереди, слева;
- клик по панели выбирает деталь и заполняет её реальную карточку;
- клик по фасаду или ящику запускает существующую анимацию открывания;
- «Открыть всё» и «Закрыть»;
- Shift+drag выбранной детали, снап и магнит;
- прозрачный режим;
- exploded view;
- габаритные размеры;
- текстуры;
- присадки;
- тела фурнитуры.

### Рабочие режимы

- 3D;
- общий чертёж;
- деталировка выбранной панели;
- раскрой;
- печать открытого чертежа или раскроя;
- связанный выбор детали между 3D и чертежом.

### Редактирование и производство

- проект: открыть, создать, переименовать, дублировать, каталог;
- изменение габаритов, материалов, архетипа и секций;
- точечные overrides выбранной детали;
- выбор фурнитуры и позиционирование ручек;
- чат по проекту и выбранной детали, изображения ТЗ, Undo, «Починить всё»;
- все проверки, статистика, смета и BOM;
- версии и восстановление;
- Save, `.cfrn`, delivery;
- платная `.b3d` только через существующий зелёный гейт и confirm;
- raw ParamSpec остаётся доступен в инженерном разделе.

## Разрешённый порядок работы

1. Запустить настоящий Studio на реальной ParamSpec:

   ```bash
   python main.py studio paramspecs/tumba_moderatora.json \
     --port 8765 --out <temp-dir> --no-open
   ```

2. Зафиксировать baseline одного и того же изделия и состояния.
3. В первой итерации менять преимущественно CSS: токены, размеры, отступы,
   визуальную иерархию, сетку и responsive-поведение.
4. DOM переставлять только при сохранении прежних `id`, обработчиков и
   доступности всех контролов.
5. JavaScript менять только когда это требуется самой компоновке; не трогать
   `MebelScene` и payload-контракты в визуальной задаче.
6. После каждой итерации перезапустить Studio и пройти parity-check.
7. Показывать review в настоящем Studio, на интерактивной модели.

## Обязательный parity-check перед передачей

Проверить в браузере:

1. модель вращается и масштабируется;
2. панель выбирается, карточка совпадает с выбором;
3. дверь и ящики открываются отдельно;
4. работают «Открыть всё» и «Закрыть»;
5. включаются и выключаются присадки, фурнитура, текстуры, размеры, x-ray;
6. работает слайдер разбора;
7. переключаются все пять камер;
8. открываются 3D, чертёж и раскрой;
9. изменение бесплатного параметра регенерирует ту же реальную модель;
10. проверки, BOM и смета остаются видимыми;
11. платная сборка не запускалась во время UI-QA;
12. консоль браузера не содержит новых ошибок.

Автоматические гейты:

```bash
cd tools/basis
python -m pytest tests/test_studio.py tests/test_webviewer.py -q
python -m tests.regression
```

Изменение нельзя передавать как готовое, если хотя бы один пункт baseline
пропал или был заменён декоративной имитацией.
