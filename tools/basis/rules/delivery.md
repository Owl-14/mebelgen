# Веб-доставка: лист согласования (AKD-15)

Инструмент живёт не в чате, а как рабочий интерфейс. **Страница проекта — источник
правды**: 3D-модель (правосторонний просмотр), спецификация (материалы, BOM
фурнитуры с артикулами, детали/раскрой, присадки ЧПУ, габарит), статус согласования.

CLI: `python main.py deliver <ParamSpec|project> [--out out] [--status draft] [--version N] [--no-export]`

## Роли

| Роль | Что делает | Видит/может |
|---|---|---|
| **Оператор производства** | готовит раскрой/сверловку, запускает в цех | детали, присадки, BOM; статус → `production` |
| **Менеджер** | ведёт согласование, общается с клиентом | все листы, смена статусов, история версий |
| **Клиентский дизайнер / клиент** | смотрит модель, согласует | 3D + параметры по ссылке; статус `review`→`approved` |

## Жизненный цикл

`draft` (черновик) → `review` (на согласовании) → `approved` (согласовано) → `production` (в производство).

Статус хранится в `metadata.json` версии и показан бейджем на листе.

## Версии и воспроизводимость

Каждый вызов `deliver` создаёт снапшот в `out/deliveries/<slug>/v<N>/`:
- `spec.json` — исходный ParamSpec (источник для повторной сборки);
- `project.json` — сгенерированные детали;
- `page.html` — лист (самодостаточный, 3D встроен во фрейм);
- `metadata.json` — версия, статус, дата, `renderer_version`, счётчики, `spec_hash`;
- `sheet.pdf`, `sheet.png` — headless-экспорт (Playwright → системный Chrome; фолбэк — Chrome CLI).

**Воспроизводимость:** лист любой версии пересобирается из её `spec.json`. При
изменении вёрстки/рендерера — поднять `RENDERER_VERSION` в `src/delivery.py`; старые
версии остаются как есть, новая сборка помечается новым `renderer_version`.

## Экспорт и ссылки

- **PDF/PNG** — кнопки на листе (`window.print()` и скачивание готовых файлов) +
  предгенерация через headless (для отправки файлом). WebGL-3D рендерится в headless.
- **Ссылка** — сейчас файловая (папка версии как статический пакет). Публичная/
  защищённая ссылка со сроком жизни и доступами — при выносе backend на сервер
  (следующий шаг); Telegram-bot может стать тонким интерфейсом поверх того же backend.

## Разделение с производственным файлом

Лист — для людей (правосторонний 3D, спецификация). Файл для БАЗИС/станка
(`.cfrn`/`.b3d`) кодируется отдельно в родной левосторонней конвенции — см.
[core.md](core.md), [hardware.md](hardware.md). Доставка его не трогает.
