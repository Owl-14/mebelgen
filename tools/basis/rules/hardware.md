# Присадки под фурнитуру (сверловка)

`src/hardware.py` `compute_drilling(project)` считает координаты отверстий из
геометрии панелей + `hardware`. Это ЧПУ-данные (где сверлить) и основа для
объектов фурнитуры в модели. Формат-независимо.

Каждое отверстие: `{panel, purpose, x, y, z, diameter, depth, axis, dir}` —
точка входа сверла в мировых координатах, ось `x|y|z`, направление `±1`.

## Кодирование в .cfrn (AKD-88)

`cfrn.py` `_encode_drilling` пишет присадки по схеме эталона `native_cabinet.cfrn`:

- `table.holes` — каталог `[{depth, diameter, drillMode}]` (уникальные, `drillMode:1`);
- объект `objType:5` `«Присадки»` с `holes:[{pos, dir, infoIndex}]` и матрицей
  (`pos` — мировые координаты, `infoIndex` → в каталог, `dir` — единичный вектор
  сверления); `triangleData:[]` — 3D-меш НЕ пишем (он из каталога БАЗИС).

Сверка кодирования — `check_cfrn_holes(project)`: реконструирует присадки из
матриц `.cfrn` и сверяет с `compute_drilling` (позиция/Ø/глубина). Наличие присадок
в самом `.b3d` подтверждается обратной выгрузкой `b3d→cfrn` из облака (round-trip).

## Правила по типам

| Фурнитура | Присадка | Правило |
|---|---|---|
| **Ручка** | 2 винта Ø5, гл 25, ось Z | На фасаде по межцентровому = `handles.size` (128/224). Ящик — горизонтально, центр, `y = верх фасада − offset_from_top`. Дверь — у кромки открывания (лев. дверь → справа, прав. → слева), 2 винта по вертикали. |
| **Петля** | чашка Ø35 гл 12 (фасад) + 2 планки Ø5 гл 12 (боковина) | Число петель по высоте двери: ≤900→2, ≤1600→3, ≤2000→4, иначе 5. Чашка в 22 мм от кромки петель, уровни равномерно между `y1+100 … y2−100`. |
| **Полкодержатель** | 4 отв Ø5 гл 10, ось X | На съёмную полку — по 2 (перед/зад) в каждую примыкающую боковину/перегородку на высоте полки. |
| **Стяжка (конфирмат)** | Ø7 гл 50, ось Y | Дно/крышка ↔ боковины/перегородки: боковина стоит на дне (стык по Y) → 2 конфирмата (перед/зад) в торец боковины на каждый стык. |
| **Направляющая** | 3 винта Ø5 гл 12, ось X | На боковинах/перегородках колонки ящика на высоте низа ящика + 12, по Z (перед/центр/зад). Шаблон под конкретную систему уточняется по `drawer_guides.type`. |

## Геометрия фурнитуры для 3D (hardware_geometry, виз-слой)

`src/hardware_geometry.py` `compute_hardware_geometry(project)` строит ВИДИМЫЕ
детали механизмов (боксы, мм) для нашего вьювера — то, на чём ящики едут и двери
висят. Это слой визуализации: в `.cfrn` меши не пишем (каталог БАЗИС — AKD-14).

**Направляющие** (пара на ящик, по обе стороны, в зазоре `guide_gap` ≈ 14.5 мм):
- корпусный полоз — на внутренней грани боковины/перегородки, толщина 7 мм;
- полоз ящика — на внешней грани боковины короба, толщина 6 мм;
- высота: шариковые 45 мм (посадка от низа короба +5), роликовые 40 мм
  (полоз ящика — под нижней кромкой боковины короба);
- длина: `hardware.drawer_guides.length_mm`, если влезает по глубине
  (`z1 + L ≤ D − T_back`), иначе стандартная вниз с шагом 50 (250…500);
- начало по Z — от фронта короба (`box z1`).

**Петли** (на каждую точку из расчёта петель: чашка + плечо + ответная планка):
- чашка Ø35, глубина 12 — во внутренней плоскости фасада (виз: бокс 35×35×12);
- плечо — от чашки через кромку двери внутрь корпуса (сечение ~18×12, вылет до
  планки, Z 0…42);
- ответная планка на боковине: 60 (высота) × 22 (глубина) × 8 (толщина), центр
  на оси петли, отступ от фронта 37 мм;
- число петель по высоте двери: ≤900→2, ≤1600→3, ≤2000→4, иначе 5 (см. таблицу).

Во вьювере фурнитура — металлик, отдельный чекбокс; в прозрачном режиме видно
механизм целиком (корпусные детали не заслоняют).

## Что даёт и не даёт

- **Даёт (без лицензии/облака):** координаты присадок под реальную фурнитуру,
  закодированные в `.cfrn` (`table.holes` + `objType:5`), + BOM с артикулами
  (`material_refs`) + ЭКЗЕМПЛЯРЫ фурнитуры (позиции+материал с артикулом,
  `catalog_hardware`). ЧПУ-готово, спецификация полна.
- **Не даёт:** 3D-меш фурнитуры. ПРОВЕРЕНО экспериментом (task 12642/12643):
  в родном формате меш подтягивается ПО ИМЕНИ из каталога (`table.triangles`
  ["<имя>.obj"], `triangleData` = индекс), но облачный CfrnToB3d каталог НЕ
  резолвит — ссылка обнуляется (материал и позиции выживают). Меш появляется
  только в десктопном Мебельщике с каталогом (AKD-14, лицензия): родной .b3d
  несёт меш внутри. Поэтому механизмы для клиента показывает НАШ вьювер
  (hardware_geometry), а .cfrn уже везёт позиции+артикулы — десктоп довесит мешы.

CLI: `python main.py hardware <project|paramspec> [--full]`.
