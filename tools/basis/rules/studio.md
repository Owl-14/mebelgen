# Akeda Studio: локальный редактор (актуальное состояние)

Правки единицы мебели ДО платной сборки через облако (~10₽). Ничего не
портируется в JS: браузер шлёт ParamSpec, Python возвращает модель/проверки/BOM.
**Один источник правды** — те же модули, что собирают `.b3d`.

Запуск: `python main.py studio <paramspec.json> [--port 8765] [--out <dir>] [--no-open]`
Сервер stdlib (`src/studio.py`), страница `PAGE` + общий 3D-движок
`webviewer.SCENE_JS`. **После правок Python сервер перезапустить** (код в памяти).

## UI (3 колонки, AKD-207)

- **Слева**: Проект (селектор изделий, +Новое → черновик, переименовать,
  дублировать, 🗂 Каталог), бейджи проверок + ошибки + статистика, карточка
  Детали (клик в 3D: габарит/материал/присадки, правка граней, чертёж детали,
  удалить, чат «про эту деталь»), Чат с ИИ (селектор нейросети, фото ТЗ
  📎/Ctrl+V/drag&drop, «⚕ Починить всё», счётчик токенов/лимитов, ⟲ откат).
- **Центр**: 3D / Чертёж / Раскрой (⎙ печать). HUD: ракурсы
  (аксон/персп/сверху/спереди/слева — `scene3d.setView`), тумблеры присадки/
  фурнитура/текстура/размеры/прозрачный, «Открыть всё/Закрыть», слайдер разбора.
  Shift+drag — двигать деталь (магнит к граням соседей, снап 1 мм).
  Клик по фасаду/ящику — анимация открытия.
- **Справа**: габариты, материал (декор корпуса/фасадов, поиск по базе со
  свотчами), опоры/зазор, архетип + его параметры, секции (тип/ящики/полки/
  двери/доли/высоты/уровни/ниши), экспорт (Сохранить / .cfrn / Собрать .b3d /
  Лист согласования / версии), фурнитура из шорт-листов базы + позиции ручек,
  смета live, BOM, raw-JSON редактор.

## Каталог изделий (AKD-217/234)

Полноэкранная витрина: карточки всех спек `paramspecs/` с **каноническим PNG-снимком
настоящего `MebelScene`** в ракурсе «Аксон». Отсутствующие и устаревшие снимки
последовательно строятся одним скрытым экземпляром общего 3D-движка и атомарно
кэшируются в `paramspecs/.previews/<stem>.png`; ревизия спеки проверяется перед записью.
Упрощённая серверная SVG-аксонометрия (`_axon_svg`) используется только как временный
фолбэк во время фонового переснимка. Разделы-чипы по типам (Тумбы/Столы/
Шкафы/Стеллажи/Черновики), живой поиск, клик — открыть. Черновики (`draft:true`,
AKD-214) — запись в каталоге + пустой воркспейс «загрузите ТЗ или опишите в чате».

Каталог — отдельный режим рабочего пространства, а не слой поверх последнего
открытого изделия. Пока каталог открыт:

- слева остаются бренд, сотрудник и нейтральный контекст «Каталог компании»;
- селектор проекта, проверки, статистика и выбранная деталь скрыты и `inert`;
- справа скрыты параметры, комплектация, производство и их rail;
- 3D-модель не очищается и не пересобирается: она остаётся в памяти только для
  корректного возврата в редактор;
- URL получает `#catalog`, `Back`/`Escape` возвращают предыдущий редактор, а
  выбор карточки открывает именно выбранное изделие.

Первый клик выбирает карточку и показывает отдельный каталоговый inspector:
превью, название, тип, габариты, материал, время изменения, автора и
ответственного. Пустые серверные поля людей честно показаны как «не назначен» /
«не указан», а не подменены локальными данными браузера. Параметры модели
появляются лишь после явного «Открыть в Studio» или двойного клика. Стрелки
перемещают выбор по сетке, `Enter` открывает изделие, первый `Escape` снимает
выбор, второй закрывает каталог. Из inspector доступны переименование,
дублирование и, при наличии object-level права, назначение активного сотрудника
компании и обратимое архивирование с обязательной причиной. Архив хранит
ParamSpec, версии, preview, AI-историю и существующие производственные файлы;
восстановление не перезаписывает занятые данные. Полный контракт — в
`ux/CATALOG_MANAGEMENT_SPEC.md`.

## API (все POST c JSON `{spec,...}`, кроме GET)

| Endpoint | Что делает |
|---|---|
| GET `/` | страница редактора |
| GET `/thumb/<spec>.json` | SVG-аксонометрия карточки (кэш) |
| GET `/preview/<stem>.png` | канонический PNG-снимок общего 3D-движка |
| `/api/generate` | ParamSpec → `{viewer, issues{6 чеков}, stats, bom, refs, estimate}` |
| `/api/techview` | чертёж SVG (+`panel` — деталировка одной детали) |
| `/api/nesting` | раскрой-превью SVG |
| `/api/chat` | ИИ-правка: `{spec,message,history,context,images,provider}` → `{reply,spec,changes,usage}`; в context — реальные кандидаты базы для нерешённых слотов и `panels` (геометрия всех деталей — для добавления/подгонки встык) |
| `/api/chat/cancel` | помечает AI-операцию отменённой; поздний ответ не пишется в историю |
| `/api/chat-history` | Серверная история AI-команд текущего изделия. В auth-режиме браузерная `history` не считается источником истины: контекст читается из tenant-хранилища |
| `/api/providers`, `/api/token-balance` | список нейросетей / лимиты выбранной |
| `/api/import-tz` | фото ТЗ → распознавание → новая спека (в черновик — тот же файл) |
| `/api/projects`, `/api/open`, `/api/new`, `/api/duplicate` | каталог/открыть/черновик/копия |
| `/api/rename`, `/api/catalog/assign` | переименовать изделие / назначить активного ответственного своей компании |
| `/api/catalog/archive`, `/api/catalog/restore` | обратимо архивировать с причиной / вернуть без перезаписи |
| `/api/catalog-preview-source`, `/api/catalog-preview` | payload указанного изделия и revision-safe кэш канонического PNG |
| `/api/reviews`, `/api/reviews/create`, `/api/reviews/revoke` | список ссылок текущего изделия / создать snapshot или live ссылку / немедленно отозвать |
| `GET /review/<token>` | публичный read-only просмотр: фиксированная либо последняя сохранённая ревизия без ParamSpec и производства; из этой же точной ревизии скачивается двухстраничный презентационный PDF |
| `POST /review/<token>/decision` | решение клиента с revision guard; устаревшая live-ревизия возвращает `409` |
| `/api/versions`, `/api/restore` | снапшоты спеки (при сохранении, до 30) |
| `/api/decors` | поиск листовых декоров базы (для поля «Из базы») |
| `/api/save` | спека в файл + `<имя>.project.json`; каноническое превью обновляется в фоне |
| `/api/export-cfrn` | бесплатный `.cfrn` |
| `/api/build-b3d` | ПЛАТНАЯ сборка; **409 при красных проверках**; после — паритет `b3d_verify` и запись в историю |
| `/api/builds`, `/api/open-file` | история сборок (расход ₽), открыть результат (в т.ч. БАЗИС-Просмотр) |
| `/api/deliver` | лист согласования (открывается в браузере) |

## Гарантии

- случайная трата на облако невозможна: кнопка неактивна при красных чеках +
  серверный 409 + confirm с ценой;
- каждая правка → полный прогон проверок (что на экране = что уйдёт в производство);
- сохранённый ParamSpec совместим со всем конвейером (deliver/viewer/build-b3d);
- пока AI считает, осмотр 3D, режимы просмотра, каталог и профиль доступны, а
  мутации ParamSpec/сохранение/экспорт временно заблокированы;
- смена изделия, новое изделие и выход во время AI требуют подтверждения и отменяют
  операцию; generation+revision guards запрещают применить поздний ответ не к той модели;
- тесты: `tests/test_studio.py` (payload, аксонометрия), `tests/test_webviewer.py`;
  e2e ИИ — `qa/e2e_ai.py`.

## Identity/admin и tenant-режим

Локальный первый срез управления компаниями запускается отдельно:

```bash
AKEDA_BOOTSTRAP_PASSWORD='<секрет минимум 15 символов>' \
python main.py admin --bootstrap-email admin@example.com
```

Studio подключается к той же identity-базе флагом `--require-auth` и путями
`--identity-db` / `--tenant-root`. В этом режиме каталог, версии, previews,
AI-история и production outputs выбираются только из компании серверной сессии;
текущее изделие хранится отдельно для каждой сессии. Клиентская `history` у
`/api/chat` игнорируется, а каждая завершённая AI-команда получает автора,
компанию, изделие, ревизии до/после и компактное событие append-only аудита.

Platform owner открывает компанию через админку и остаётся настоящим актором;
Studio показывает постоянный support-banner и разрешает только чтение.
Контракт и этапы — в `rules/identity-access.md`,
`ux/IDENTITY_ACCESS_ADMIN_SPEC.md` и `ux/DEMO_COMPANY_AND_ADMIN_VIEW_SPEC.md`.
