# Правила построения модели для БАЗИС

Одно правило важнее всех: **каждое ТЗ считается заново**. Между проектами
переносится только метод (координаты, формулы, типы деталей, формат JSON) —
никогда не сами `placement` из чужого проекта.

## 1. Система координат (`basis_mebelshik`)

- Начало `(0,0,0)` — левый нижний **передний** угол корпуса.
- `X` — ширина вправо, `Y` — высота вверх, `Z` — глубина назад (0 — перёд, `D` — зад). Единицы — мм.
- У каждой панели обязателен `placement` — габаритный бокс `{x1,x2,y1,y2,z1,z2}`. Скрипт ставит **GabMin** панели в `(x1,y1,z1)`.
- `rotation` всегда 0 — повороты в JSON не используются.

### Ориентация панели

| `basis_orientation` | Детали | `NewPanel(W,H)` | dimensions = |
|---|---|---|---|
| `horizont` | дно, крышка, полки, дно ящика | `(spanX, spanZ)` | X × Z |
| `vertical` | боковины, перегородки, боковины ящика | `(spanZ, spanY)` | Z × Y |
| `front` | фасады, задняя стенка, задняя ящика | `(spanX, spanY)` | X × Y |

`dimensions` — производное от `placement`. Источник истины — `placement`
(`check-consistency --fix-dimensions` приводит одно к другому).

## 2. Корпус (`top_bottom_over_sides`)

`W,D,H` — габарит; `T` — толщина ЛДСП; `Hleg` — высота опор (0, если нет);
`T_back` — толщина задней стенки.

```
Y_дно   = Hleg .. Hleg+T
Y_бок   = Hleg+T .. H-T          // боковины между дном и крышкой
Y_крышка = H-T .. H

Дно/крышка:  x 0..W,        z 0..D
Боковины:    x 0..T и W-T..W, y Y_бок,  z 0..D
Задняя:      x T..W-T,       y Y_бок,   z D-T_back..D
```

Низ корпуса стоит на `y = Hleg`; верх — на `y = H`. Если есть цоколь —
он отдельная панель `0..Hleg` (тогда `legs.height = Hleg`).

## 3. Зазоры

- Фасады: `z 0..T` (перёд). Если в БАЗИС «выпирают» — `z -T..0`.
- Полки/перегородки: `z T .. D-T_back` — не входить в фасад и в задник.
- Зазор фасадов `gap = constraints.drawer_gap` (обычно 2 мм).

### Фасадная полоса по высоте (N ящиков/дверей)

```
Y_низ  = Y_бок_низ + gap
Y_верх = Y_бок_верх - gap
H_один = (Y_верх - Y_низ - (N-1)*gap) / N
k = 0..N-1:  y1 = Y_низ + k*(H_один+gap);  y2 = y1 + H_один
```

## 4. Тумбы (применять только для тумб/тумбочек)

Включать эти правила, если в ТЗ явно «тумба/тумбочка/тумба под …». Для стоек,
кашпо, стеллажей, шкафов-купе — **не** включать (строить общий корпус по §1–3).

- **Стек ящиков**: никаких стационарных перемычек между ярусами. Каждый ящик —
  отдельный короб: дно, 2 боковины, задняя, фасад. Ярус `k` привязан к своей
  паре `y1_k..y2_k` из §3.
- **Короб ящика** (внутр. ширина секции `Sw`): дно `x=X_внутр..+Sw`; боковины
  по краям толщиной `T`; задняя смещена назад под направляющие.
- **Дверь поверх нижнего проёма**: если полка делит корпус на открытый верх и
  закрытый низ, `door_front` закрывает только низ — `y2_door = y1_полки - gap`.
- **Врезные двери в проём**: по X `x1=T+gap .. x2=X_перегородки-gap`.
- **Две глубины** (ТЗ вида `D_полн/D_корпус`, напр. 350/270): корпус
  `z 0..D_корпус-T_back`, задник за ним, столешница — со свесом вперёд.

## 5. Фурнитура

- `handles`: скрипт ставит ручки только при `count > 0`. Точка — центр фасада по X,
  `y = y2 - offset_from_top`, `z = z1` фасада (координаты в ГСК из `placement`).
- `drawer_guides` / петли / замки: требуют каталога поставщика. До него — пусто
  (в `warnings`) либо мастера БАЗИС «Установка ящиков/дверей». Реальная строка
  `furniture_encoded` берётся выбором фурнитуры в БАЗИС при первом импорте.

## 6. Рабочий процесс (для агента)

После создания или правки любого JSON агент **сам** прогоняет проверки и
сообщает пользователю результат (не список команд):

```
python main.py finish projects/<project>.json     # схема + геометрия + автофикс полок
python main.py check-consistency projects/<project>.json   # placement↔dimensions↔габарит
```

Реакция на проблемы `finish`:

| Сообщение | Действие |
|---|---|
| Ошибки схемы | поправить JSON, повторить |
| `split_horizontal_*` остаётся после автофикса | разделить полку в JSON вручную |
| `adjust_vertical_or_merge` | не дробить стойки; сдвинуть/объединить детали по ТЗ |

Затем — импорт в БАЗИС (`scripts/ImportFurnitureFromJSON.js` + JSON) и сверка с чертежом.
