# Akeda Studio — нижняя AI-команда и журнал изменений

Связанная задача: `MEB-095`, следующий срез `MEB-099`.

Статус: `APPROVED LOCAL BASELINE`. Документ описывает второй вертикальный
срез поверх настоящего Studio. Он не меняет `MebelScene`, ParamSpec, генераторы,
API, камеру, выбор деталей или анимацию створок.

## Разделение ролей

AI не оформляется как постоянная переписка рядом с моделью. Интерфейс разделён
на три разные роли:

1. нижняя строка по центру — ввести команду, увидеть её контекст и отправить;
2. короткий transient-status над строкой — понять, что реально происходит сейчас;
3. журнал `Изменения` слева — прочитать содержательный ответ, diff и ошибку позже.

Если ответ сводится к «готово», отдельный текст не раздувает viewport: строка
показывает `Готово · N изменений`. Если AI дал объяснение или технический diff,
они остаются в журнале. Кнопка `Изменения` у краткого итога прокручивает левую
панель к журналу; `Отменить` выполняет существующий атомарный Undo.

## Почему так

- Photoshop держит contextual action у холста, а развёрнутый результат — в
  Properties.
- Figma Make отделяет prompt от хода работы и финальной сводки.
- Cursor отделяет команду от Review changes и точки восстановления.
- Для CAD постоянная история операций полезнее ленты chat bubbles.

## Решение по выбору детали

Одинарный клик не раскрывает правую колонку и не меняет ширину viewport.
Он:

- сохраняет существующую подсветку `MebelScene`;
- показывает существующую карточку `fs_part` слева;
- меняет подпись command dock на `Выбранная деталь · <имя>`;
- передаёт тот же `selected_part` в `/api/chat`.

Полный правый inspector выбранной детали требует отдельного контекстного режима.
До его проектирования глобальная длинная панель параметров автоматически не
открывается.

## Информационная архитектура

```text
┌────────── слева ──────────┐  ┌──────────── настоящий viewport ────────────┐
│ Проект                    │  │  3D / чертёж / раскрой                    │
│ Состояние модели          │  │                                            │
│ Выбранная деталь          │  │                                            │
│                           │  │         [текущий этап · действия]          │
│ Изменения                 │  │  [контекст][команда........][ТЗ][Выполнить]│
│ Команда                   │  └────────────────────────────────────────────┘
│ Результат + diff          │
└───────────────────────────┘
```

Нижняя строка занимает только свой прямоугольник. Вне неё pointer events идут в
`MebelScene`, поэтому вращение, выбор и открывание мебели не меняются. Панель не
добавляет padding в viewport и не запускает resize/rebuild сцены.

## Визуальная система

- `instrument-ink`: `#1a1d21`;
- `instrument-muted`: `#687180`;
- `instrument-line`: `#d9dee5`;
- `instrument-surface`: `#ffffff`;
- `instrument-canvas`: `#f4f6f8`;
- `selection-blue`: `#3b82f6`;
- status green/warning/red используются только для реальных состояний.

Segoe UI остаётся рабочим шрифтом интерфейса, Consolas — только для diff и
инженерных данных. Секции разделяются линиями, без карточных теней, blur,
градиентов и декоративных AI-эффектов. Локальные SVG имеют одну геометрию.

Характерный элемент — инженерная command rail: почти непрозрачная светлая
поверхность, тонкая линия, компактный контекст модели/детали и единственный
движущийся элемент — индикатор настоящей незавершённой операции. Нет blur,
glow, градиентов, декоративных искр и фальшивых процентов.

## Состояния command dock

| Состояние | Что видно |
|---|---|
| Empty | контекст, одна строка команды, вложение, `Выполнить` |
| Selected part | контекст и placeholder содержат имя выбранной детали |
| Attachments | миниатюры идут горизонтально и не раздувают rail |
| Request | `Разбираю команду и контекст…`; повторная отправка заблокирована |
| Recalculate | `Пересчитываю модель и инженерные проверки…` |
| Success | `Готово · N изменений`, `Изменения`, атомарный `Отменить` |
| Informational answer | `Ответ готов · подробности слева`, без ложного Undo |
| Error | текст и вложения возвращены; ошибка записана слева |
| Fix all | показан реальный номер прохода; финальный результат остаётся в журнале |

## Инженерная запись операции

Текущий локальный срез `UX-021` заменяет пары «команда / ответ AI» одной
обновляемой записью. Это не визуальная карточка и не chat bubble: записи идут
единым журналом, разделяются hairline-линиями, а состояние обозначает узкая
цветная рейка.

Запись сохраняет только подтверждённые данные:

- исходную команду, время, провайдера, количество вложений и снимок контекста;
- до трёх строк ParamSpec diff в виде `параметр: до → после`;
- полный технический diff и содержательный ответ в `Подробнее`;
- снимок инженерных проверок и нерешённых позиций базы сразу после пересчёта;
- действие `Показать`, только если деталь из контекста ещё есть в текущей модели;
- действие `Отменить`, только если запись всё ещё соответствует верхней ревизии
  `UNDO` и текущий `SPEC` не менялся.

| Состояние записи | Смысл |
|---|---|
| В работе | запрос отправлен или модель пересчитывается |
| Применено | новый `SPEC` успешно прошёл генерацию и вернул реальный viewer |
| Применено с вопросами | модель пересчитана, но проверки или база требуют внимания |
| Ответ | модель не изменялась; показан только содержательный ответ |
| Не выполнено | исходная модель восстановлена, команда и вложения возвращены |
| Отменено | модель успешно пересчитана из предыдущего snapshot |

`Исправить проблемы` агрегируется в одну запись с реальными проходами. Поскольку
один запуск может создать несколько snapshots, запись не обещает атомарный Undo
всего цикла; глобальный Undo по-прежнему может отменить только последний проход.

Во время незавершённой команды панели, меняющие `SPEC`, временно заблокированы.
Кроме того, перед применением ответа сверяется исходный JSON и поколение
открытого изделия. Поэтому поздний ответ не может молча затереть ручную правку
или другой проект.

## Неприкосновенные контракты

Сохраняются все текущие рабочие ID, payload `/api/chat`, provider, attachments,
`CHAT_HISTORY`, `UNDO`, `fixAll`, импорт ТЗ и выбранный `SELECTED_PART`.
`chatlog` только меняет родителя. Платные B3D/Cutting операции не вызываются.
