# Akeda Studio UX — рабочий процесс

Этот каталог — общая память продуктовой и интерфейсной работы. Он нужен, чтобы
новая задача или новый чат продолжали согласованный процесс, а не начинали
редизайн заново.

## Как принимаются решения

1. Сначала описываем работу пользователя и необходимую обратную связь.
2. Затем проверяем, какие функции уже существуют в живом Studio.
3. Только после этого определяем расположение, текст, состояние и вид контрола.
4. Макет строится вокруг снимка настоящего `MebelScene`.
5. Пользователь отдельно согласует каждый крупный экран и состояние.
6. В код переносится один вертикальный срез за раз.
7. Каждый срез проходит функциональный parity-check.

Статусы:

- `APPROVED` — решение прямо подтверждено пользователем;
- `HYPOTHESIS` — рабочее предложение, которое нужно проверить;
- `OPEN` — продуктовый вопрос без принятого решения;
- `REJECTED` — направление запрещено или отброшено.

## Текущий проект: visual refresh без перестройки продукта

| № | Этап | Статус | Результат | Review gate |
|---|---|---|---|---|
| 1 | Scope и baseline | DONE | Пользователь, текущий процесс, неприкосновенная 3D-сцена, visual-only граница | Граница подтверждена пользователем |
| 2 | Визуальный аудит Studio | IN PROGRESS | Разбор каждого существующего блока и состояния без изменения поведения | Пользователь видит и обсуждает аудит по зонам |
| 3 | Визуальные направления | QUEUED | 2–3 style boards на одной реальной сцене | Выбран характер продукта |
| 4 | High-fidelity visual pass | QUEUED | Текущий экран Studio, причёсанный в Figma без нового workflow | Согласован каждый уголок экрана |
| 5 | CSS/HTML implementation | QUEUED | Та же страница и функции в новой визуальной оболочке | Живой review в настоящем Studio |
| 6 | Parity и visual QA | QUEUED | Функциональная и screenshot-регрессия | Ни одна функция и ни один аспект 3D не изменены |

## Отдельный поток клиентского согласования

Read-only просмотр реализуется отдельным этапом MEB-104: фиксированная или
обновляемая ссылка, срок действия, отзыв, комментарий, вложения и решение,
привязанное к ревизии. Из той же показанной ревизии клиент скачивает
двухстраничный презентационный PDF с изометрией и exploded; производственные
данные в него не входят. Этот поток не меняет AI/3D-движок.
