# MEB-114 — безопасное управление изделиями в каталоге

Статус: **IMPLEMENTED LOCALLY / AWAITING REVIEW**.

Цель первого среза — позволить владельцу или ответственному сотруднику
переименовать изделие, назначить ответственного и убрать изделие из рабочего
каталога без необратимого удаления данных. Геометрия и поведение `MebelScene`
не меняются.

## Пользовательский сценарий

1. Сотрудник открывает общий каталог компании.
2. Первый клик по карточке выбирает изделие и открывает каталоговый inspector.
3. Если у сотрудника есть право на конкретное изделие, он может:
   - изменить название;
   - назначить активного сотрудника своей компании ответственным;
   - переместить изделие в архив, обязательно указав причину.
4. В разделе `Архив` видны причина, время и автор архивирования.
5. Разрешённый сотрудник может вернуть изделие в рабочий каталог.

Архив — отдельное состояние каталога, а не окончательное удаление. Изделие из
архива нельзя открыть в Studio до восстановления.

## Права первой версии

- `owner` компании управляет всеми её изделиями;
- создатель изделия и текущий ответственный управляют своим изделием;
- остальные сотрудники могут видеть доступное им изделие, но не получают
  кнопки управления и получают серверный `403` при прямом запросе;
- назначить можно только активного участника текущей компании;
- demo-каталог и support-просмотр Akeda остаются неизменяемыми;
- permission `project.write` проверяется до object-level проверки и не заменяет
  её.

Все решения принимаются по данным проверенной серверной сессии. Клиент не
передаёт доверенный `organization_id`.

## Что хранит архив

Для tenant-компании bundle находится в
`<tenant-root>/<organization-id>/archive/<archive-id>/`, для legacy-режима — в
`paramspecs/.archive/<archive-id>/`. В bundle входят manifest и существующие на
момент операции:

- ParamSpec изделия;
- история версий;
- каноническое PNG-превью;
- история AI-команд;
- `.project.json`, `.cfrn`, `.b3d`;
- каталог delivery с листами согласования и сопутствующими файлами.

Производственные outputs остаются на исходном месте, чтобы не ломать ссылки в
истории сборок, но их неизменяемая копия также входит в bundle. ParamSpec
исчезает из рабочего каталога только после завершения полной копии.

## Атомарность и конфликты

- архив сначала собирается в staging-каталоге, затем атомарно становится
  готовым bundle;
- при любой ошибке уже снятые с рабочего места файлы возвращаются из bundle;
- архивирование и восстановление сериализованы внутри многопоточного Studio;
- ParamSpec при восстановлении появляется последним;
- восстановление никогда не перезаписывает существующий ParamSpec, версии,
  preview или AI-историю;
- совпадение названия с активным изделием возвращает `409 name_conflict`;
- повреждённый manifest не может выйти за tenant-root или выбрать неизвестный
  корень восстановления;
- каждое переименование, назначение, архивирование и восстановление пишется в
  append-only audit с реальным actor и organization.

## Интерфейс первого среза

- в навигации каталога появились `Все изделия`, `Мои`,
  `Без ответственного`, `Архив` со счётчиками;
- ответственный меняется прямо в inspector, без открытия 3D;
- архивирование открывает отдельный диалог с названием изделия, объяснением
  сохранности данных и обязательной причиной;
- архивная карточка показывает контекст операции и только допустимое действие
  `Вернуть в каталог`;
- список активных сотрудников, права карточки и архивные данные приходят с
  сервера; интерфейс не вычисляет авторизацию самостоятельно.

## API первого среза

| Endpoint | Назначение |
|---|---|
| `POST /api/projects` | Активный каталог или архив, счётчики, сотрудники и object-level `can_manage` |
| `POST /api/rename` | Переименование с нормализацией и проверкой конфликта |
| `POST /api/catalog/assign` | Назначение активного сотрудника текущей компании |
| `POST /api/catalog/archive` | Обратимое архивирование с обязательной причиной |
| `POST /api/catalog/restore` | Восстановление без перезаписи активных данных |
| `GET /archive-preview/<archive-id>` | Закрытое session-auth превью архивной карточки |

## Review gate

- владелец проходит rename → assign → archive → restore в локальной Studio;
- другой designer/reviewer не может управлять чужим изделием;
- сотрудника другой компании или заблокированного сотрудника назначить нельзя;
- архив и восстановление проверены с версиями, preview, AI-историей и outputs;
- после полного тестового прогона отсутствует diff в `src/webviewer.py`.
