# Akeda Studio — визуальная система

Статус: `HYPOTHESIS / LOCAL REVIEW`
Задача: `MEB-094`
Дата: 2026-08-11

## Зачем она нужна

Akeda Studio — плотный desktop-инструмент проектировщика мебели. Его задача —
дать максимум внимания настоящей 3D-модели и инженерному решению, а не выглядеть
как маркетинговый сайт или общая админка. Эта спецификация фиксирует общие
правила, по которым дальше собираются панели, тулбары и состояния.

## Выбранное направление: «спокойный инженерный стол»

Это не новая тема и не перерисовка MebelScene. За основу берётся уже
согласованный светлый Studio:

- ровный нейтральный фон viewport;
- белые поверхности для боковых панелей и инструментов;
- тонкие серые линии вместо карточек, теней и декоративных блоков;
- синий цвет только для текущего выбора, focus и основного действия;
- зелёный, жёлтый и красный — только для реальных статусов модели;
- плотная сетка и точные подписи, как у профессионального CAD/CAM.

Направления, которые **не** используются: glassmorphism, тёмный neon-HUD,
лендинг с крупным hero-блоком, KPI-карточки, декоративные градиенты и
«магические» AI-эффекты.

## Токены

| Роль | Значение | Где использовать |
|---|---:|---|
| `--ink` | `#1A1D21` | основной текст и иконки |
| `--mut` | `#6B7280` | вторичные подписи и подсказки |
| `--line` | `#DFE3E8` | границы поверхностей и разделители |
| `--bg` | `#F4F6F8` | нейтральный фон рабочей области |
| `--card` | `#FFFFFF` | панели, поля, меню |
| `--accent` | `#3B82F6` | активная вкладка, focus, главная команда |
| `--ok` | `#2FA84F` | только валидная модель / доступность производства |
| `--warn` | `#C78A2B` | ожидает пересчёта, требуется внимание |
| `--bad` | `#E5484D` | фактическая ошибка или опасное действие |

Семантика обязательна: цвет не является единственным носителем статуса — рядом
всегда есть понятный текст, иконка либо оба сигнала.

## Типографика и числа

- Основной интерфейс: `Segoe UI, Arial, sans-serif`.
- Обычный текст: `13px`; подписи и вспомогательный текст: `10.5–12px`.
- Заголовок группы: `12px`, semibold, sentence case.
- Инженерные числа: tabular figures; `Consolas, monospace` допустим только
  внутри числовых вводов, координат и точных значений.
- Никаких капслок-заголовков, рекламных формулировок и обрезанных названий
  значимых рабочих разделов.

## Сетка и поверхности

| Элемент | Правило |
|---|---|
| Базовый шаг | 4px; обычные интервалы 6 / 8 / 12 / 16px |
| Панели | белая плоскость + `1px` линия; без тяжёлой тени |
| Поля | высота 30px, радиус 4px, явная подпись вне placeholder |
| Кнопки | текст для редкого инженерного действия; icon-only — только знакомая команда с tooltip и `aria-label` |
| Вкладки | выбранное состояние = нижняя линия и синий текст; названия не обрезаются |
| Секции | одна поверхность, hairline-разделители; длинные детали раскрываются через `details` |
| Viewport | получает оставшееся место; его фон не превращается в декоративный элемент |

## Состояния компонентов

| Состояние | Визуальное правило | Текст / поведение |
|---|---|---|
| Default | белая поверхность, нейтральная линия | действие доступно |
| Hover | только лёгкое изменение фона или текста | без подъёма, glow и bounce |
| Focus | `2px` accent outline | виден для клавиатуры |
| Selected | accent-line / accent text | показывает текущий инструмент или режим |
| Disabled | сниженная контрастность + `cursor:not-allowed` | причина объяснена рядом, если она не очевидна |
| Busy | действие блокируется, 3D остаётся осматриваемой | коротко сообщает этап: «Пересчёт…», «Выполняю…» |
| Warning | `--warn` + текст | модель ждёт решения или пересчёта |
| Error | `--bad` + текст | что именно не так и как продолжить |
| Empty | короткая причина + следующее действие | не оставлять пустую белую область |

## Иконки и motion

- Единственная система: локальные inline SVG с outline-штрихом `1.8`,
  round linecap/linejoin. Внешние CDN и смешение наборов запрещены.
- Размеры: 16px в строках, 18px в toolbar/rail, 20px только для крупной
  навигации. Иконка не заменяет подпись там, где действие редкое или опасное.
- Hover/focus: 120–160ms; toast и смена локального состояния: 180–220ms.
  Анимация объясняет факт действия, не украшает экран.
- При `prefers-reduced-motion: reduce` декоративные переходы отключаются.

## Граница реализации

Эта система применяется только к оболочке Studio в `src/studio.py`. Она не
меняет `src/webviewer.py`, сцену, камеры, выбор, механику мебели, ParamSpec,
генераторы или API. Перед первым общим CSS-проходом нужен отдельный локальный
review на настоящем Studio; затем правила фиксируются в Figma на скриншотах
живой MebelScene, а не на вымышленной мебели.

- [ ] Проверен `prefers-reduced-motion`.
- [ ] `git diff --exit-code <base> -- src/webviewer.py` проходит.
