# Akeda Studio — компактная карточка выбранной детали

Связанное решение: `UX-022`.

Статус: `HYPOTHESIS / LOCAL REVIEW`. Документ фиксирует реализованный
вертикальный срез настоящего Studio. Он не меняет `MebelScene`, генераторы,
ParamSpec, производственные проверки или устройство глобальной правой панели.

## Назначение и граница

Обычный клик по детали оставляет 3D главным рабочим пространством и обновляет
компактную секцию `Выбранная деталь` слева. Глобальная правая панель при выборе
не раскрывается.

Карточка решает три задачи:

1. идентифицирует выбранную деталь и её происхождение;
2. показывает доступные сейчас производственные данные;
3. даёт короткий путь к словесной команде, чертежу и точной правке граней.

Материал, кромка и присадки в этом срезе только отображаются. Карточка не
имитирует отсутствующие локальные редакторы этих данных и не становится вторым
полным inspector.

## Источники данных

В карточке нет fixture или дублирующей модели состояния. Она читает только
текущие данные Studio:

- имя, тип, XYZ, толщина, материал и кромка — из выбранной панели
  `lastPayload.viewer.panels`;
- присадки — из `lastPayload.viewer.holes`, отфильтрованных по имени панели;
- происхождение — из реального `SPEC.overrides`;
- состояние модели после правки — из свежего ответа `/api/generate`.

Тип детали переводится в пользовательское название локальным словарём. Если
тип неизвестен, сохраняется исходное значение. Габарит подписан как
`Габарит XYZ`: payload не содержит локальную ориентацию пласти, поэтому
называть эти три мировых размера шириной, высотой и глубиной было бы неточно.

## Иерархия

```text
Выбранная деталь                              снять выбор
Имя детали                         От генератора / Локальная правка
Тип детали
───────────────────────────────────────────────────────────────
Габарит XYZ    X × Y × Z мм
Материал       материал · толщина
Кромка         толщина · количество торцов
Присадки       количество · количество типов
───────────────────────────────────────────────────────────────
Изменить словами                         Чертёж
Нижняя команда уже адресована выбранной детали.
───────────────────────────────────────────────────────────────
Точные параметры  ▸
```

Секции разделяются линиями и типографикой. Постоянного карточного фона, тени,
blur, glow, декоративного AI-эффекта или набора KPI-плиток нет. Компоновка
остаётся рабочей при ширине левой панели `270–340 px`: подписи и значения
используют `minmax(0, 1fr)`, действия не создают горизонтальный overflow, числа
имеют табличное начертание.

## Действия

- `Снять выбор` вызывает существующий `scene3d.select(null)`; `Esc` выполняет
  то же действие, если нет неприменённого точного ввода.
- `Изменить словами` фокусирует канонический нижний `#chatMsg`. Выбранная
  деталь уже указана в `#chatContextLabel` и передаётся в `/api/chat`.
- `Чертёж` открывает реальную деталировку этой панели через `/api/techview`.
- `Точные параметры` раскрывает inline-редактор мировых граней `x1/x2`,
  `y1/y2`, `z1/z2` и рассчитанные дельты по осям.
- `Применить` создаёт или обновляет реальный transform override.
- `Отменить ввод` возвращает поля к последней рассчитанной модели; это не
  глобальный Undo.
- `Сбросить к результату генератора` доступно только для transform override.
- `Удалить деталь…` требует подтверждения и затем создаёт delete override;
  вручную добавленная деталь удаляется из списка overrides.

Отдельный локальный AI-input визуально не показывается. Legacy `partChat` и
`partChatSend` сохранены скрытыми для совместимости, но единственная видимая
точка ввода — утверждённая нижняя command rail.

## Точный ввод, транзакция и проверки

Редактор принимает только конечные числа и требует:

```text
x1 < x2
y1 < y2
z1 < z2
```

Пока значения совпадают с рассчитанной панелью, `Применить` и `Отменить ввод`
неактивны. При валидном изменении показывается `Есть неприменённые значения`;
при неверной паре — `Проверьте границы: начало оси должно быть меньше конца`.

Любая точечная мутация выполняется через один транзакционный путь:

1. сохраняются снимки `SPEC` и стека `UNDO`;
2. редактирование Studio блокируется от параллельной AI- или ручной мутации;
3. override записывается в ParamSpec;
4. Studio ожидает полный `/api/generate` и все штатные проверки;
5. ответ применяется только если он не устарел относительно текущего `SPEC`;
6. выбранная панель повторно выбирается по имени в свежем payload;
7. при ошибке `SPEC` и `UNDO` восстанавливаются, затем возвращается исходная
   рассчитанная модель.

Карточка не меняет геометрию самостоятельно: координаты по-прежнему применяет
слой overrides, а итог рассчитывает детерминированный конвейер. Shift-drag
использует тот же транзакционный путь. Во время пересчёта конкурирующие
действия заблокированы.

## Состояния

| Состояние | Что видно и доступно |
|---|---|
| Нет выбора | `fs_part` скрыта; нижняя команда относится ко всему изделию |
| Выбрано, от генератора | имя, человекочитаемый тип, реальные факты и основные действия |
| Локальная правка | происхождение `Локальная правка`; доступен сброс transform override |
| Добавлено вручную | происхождение `Добавлена вручную`; деталь можно удалить |
| Exact clean | текущие грани и дельты; Apply неактивен |
| Exact dirty | `Есть неприменённые значения`; доступны Apply и отмена ввода |
| Exact invalid | объяснение ошибки границ; Apply неактивен |
| Пересчёт | `Пересчитываю деталь и проверки…`; ввод и мутации заблокированы |
| Успех | `Точные параметры применены`, `Положение детали изменено` или сообщение сброса |
| Ошибка | `Не удалось применить. Исходная модель сохранена`; исходные `SPEC` и Undo восстановлены |
| Деталь удалена/исчезла | выбор снимается, карточка скрывается; восстановление доступно через глобальный Undo |

Если `Esc` нажат при открытом exact-редакторе с неприменёнными значениями,
сначала отменяется ввод и закрывается disclosure. Следующий `Esc` снимает выбор.

## Неприкосновенные контракты

- `src/webviewer.py`, `SCENE_JS` и публичный API `MebelScene` не изменяются;
- OrbitControls, raycast, выбор, Shift-drag, снап, открывание дверей и ящиков,
  присадки, фурнитура, размеры и камеры работают как раньше;
- `scene3d.onSelect`, `scene3d.select` и `scene3d.onTransform` используются как
  существующие точки интеграции, а не заменяются альтернативной сценой;
- обычный выбор детали не вызывает `setRightPanel()`;
- платные `.b3d` и Cutting-операции для review не запускаются.

## Review checklist

1. На реальном изделии кликнуть корпусную панель, фасад и деталь ящика;
   проверить имя, тип, XYZ, материал, кромку и присадки.
2. Убедиться, что обычный клик не раскрывает глобальную правую панель и не
   меняет ширину viewport.
3. Проверить, что `Изменить словами` фокусирует нижнюю строку, а её контекст
   содержит имя выбранной детали.
4. Открыть `Чертёж`; сравнить имя, размеры, кромку и присадки с карточкой.
5. Ввести невалидную пару граней; Apply должен остаться неактивным, а причина
   должна быть написана словами.
6. Применить валидную правку; дождаться пересчёта, сохранения выбора и свежих
   проверок, статистики, BOM и сметы.
7. Проверить `Отменить ввод`, глобальный Undo и `Сбросить к результату
   генератора`.
8. Проверить подтверждение удаления и восстановление через Undo.
9. Проверить Shift-drag и блокировку параллельной команды во время пересчёта.
10. Проверить двухступенчатый `Esc`: сначала exact-draft, затем выбор.
11. Проверить ширины `270 px` и `340 px`, keyboard focus и отсутствие
    горизонтального overflow.
12. Повторить parity-check `3D / Чертёж / Раскрой` и убедиться, что в консоли
    нет новых ошибок.
13. Выполнить тесты Studio/Webviewer, полный regression и гейт:

    ```bash
    git diff --exit-code HEAD -- src/webviewer.py
    ```
