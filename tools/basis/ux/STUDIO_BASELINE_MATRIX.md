# Akeda Studio — baseline и parity-матрица

Связанная задача: `MEB-093`.

Статус: `IN PROGRESS`. Документ фиксирует настоящий production Studio до
визуальных изменений. Он не является макетом нового интерфейса.

## Неприкосновенный контракт 3D

В рамках UX-эпика не меняются `src/webviewer.py`, `MebelScene`, payload сцены,
геометрия и визуальный результат мебели, свет, камеры, OrbitControls, raycast,
выбор, Shift+drag, анимации дверей и ящиков, присадки, фурнитура, размеры,
x-ray и exploded view.

Автоматический гейт любой визуальной ветки:

```bash
git diff --exit-code <base> -- tools/basis/src/webviewer.py
```

## Принятое решение компоновки №1

Утверждён вариант A (`UX-017`): 3D является постоянным рабочим центром.

- до 1599 px правая панель по умолчанию свёрнута в rail шириной 48 px;
- rail открывает параметры, комплектацию или производство в существующей
  правой панели;
- на ширине от 1600 px обе панели по умолчанию открыты;
- ручной выбор пользователя сохраняется до перезагрузки страницы;
- текущий срез меняет только ширину и навигационную оболочку. Полноценный
  контекстный inspector выбранной детали выполняется отдельным review-срезом.

Фактическая встроенная ширина 1087 px теперь распределяется как 270 px слева,
769 px для центральной области и 48 px для rail. При открытии правой панели
центр возвращается к прежней ширине 517 px.

## Локальное решение компоновки №2

Три кнопки rail открывают не позицию в длинном документе, а отдельный режим:

- `Параметры` — конструкция изделия и инженерный raw ParamSpec;
- `Комплектация` — фурнитура, смета и BOM;
- `Производство` — сохранение, версии и передача результата.

В открытой панели те же режимы доступны через sticky tablist. Скрытые режимы
остаются в DOM для штатного обновления данных, но имеют `hidden + inert`.
