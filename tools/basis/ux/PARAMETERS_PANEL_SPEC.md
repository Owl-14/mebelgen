# Akeda Studio — верх режима «Параметры»

Статус: `HYPOTHESIS / LOCAL REVIEW`
Дата: 2026-08-04

## Задача среза

Проектировщик должен быстро прочитать и изменить основные решения изделия, не
прокручивая длинную веб-форму: габариты, декоры, тип конструкции, его параметры,
высоту опор и фасадный зазор. Это существующие данные `ParamSpec`; новый уровень
модели или новый способ расчёта не добавляется.

Динамические `Секции` намеренно не входят в этот срез. Они требуют отдельного
разбора структуры, названий и взаимозависимостей, а не косметического сжатия.

## Информационная иерархия

```text
Габариты
W Ширина       D Глубина       H Высота
[ 1000 ] мм    [ 400 ] мм      [ 750 ] мм

Материал
Корпус   [ Серо-коричневый тёмный ] [swatch]
Фасады   [ Как корпус             ] [swatch]
Код декора                    Толщина плиты
[ U740 ST9 ]                  [ 16 ] мм
Найти в базе материалов
[ Дуб, белый, артикул…                         ]

Конструкция
Тип изделия                   [ cabinet       ]
Параметры конструкции         [ реальные data-ak поля ]

Установка
Высота опор                   Фасадный зазор
[ 60 ] мм                     [ 2 ] мм
```

Характерный элемент — одна трёхосевая строка `W / D / H`. Она не является KPI
или декоративной карточкой: каждое значение — настоящее редактируемое поле,
которое сразу попадает в прежний `harvest()` и запускает обычный пересчёт.

## Визуальный контракт

- одна белая поверхность и hairline-разделители между группами;
- `Segoe UI` для подписей, `Consolas` только для числовых инженерных значений;
- поля высотой `30 px`, радиусом `4 px`, без теней, blur и градиентов;
- ось и название стоят над каждым габаритом; единица `мм` показана рядом, но не
  записывается в `input`;
- корпус и фасады образуют явную пару, а их реальные swatch остаются связаны с
  текущим viewer payload;
- код декора и толщина плиты находятся на одном уровне решения;
- поиск производственной базы остаётся отдельным полноширинным действием;
- на ширинах inspector `300 / 330 / 360 px` нет горизонтального scroll.

## Поведение и parity

- сохранены исходные ID `f_w`, `f_d`, `f_h`, `f_color`, `f_facade_color`,
  `f_code`, `f_t`, `decorQ`, `archSel`, `f_legs`, `f_gap`;
- `fillForm()` по-прежнему заполняет все значения, `harvest()` записывает их в
  `SPEC`, а общий `input` listener запускает `schedule()`;
- поиск декоров продолжает использовать `/api/decors`; выбор строки применяет
  материал корпуса, кнопка `Ф` — фасадов;
- поля архетипа сохраняют `data-ak`; им добавлены только стабильные `id` и
  связанные `label[for]`;
- смена архетипа остаётся структурной правкой с Undo и `apply()`;
- `MebelScene`, Three.js, камеры, геометрия, материалы сцены и `webviewer.py` не
  меняются.

## Review checklist

- [ ] W/D/H читаются одной инженерной строкой и остаются удобными при `300 px`;
- [x] длинные названия корпуса и фасадов не ломают ширину панели;
- [x] поиск базы показывает отдельные keyboard-действия для корпуса и фасадов;
- [x] динамические параметры текущего архетипа имеют понятные подписи и focus;
- [x] изменение ширины даёт честное состояние «ожидает пересчёта → актуальна»;
- [x] переход между тремя режимами не сбрасывает введённые значения;
- [x] 3D, выбор детали, чертёж и раскрой сохраняют parity; `MebelScene` не менялся;
- [x] браузерная консоль не содержит новых ошибок.
