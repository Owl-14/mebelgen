# Формат отверстий и фурнитуры в .cfrn (реверс эталона, AKD-149)

Эталон: `D:\claude\bazis\out\native_cabinet.cfrn` — родной шкаф Мебельщика
(26 объектов: 25 панелей + ручка-кнопка, 4 инстанса, 2 типа отверстий).
Дополняет docs/BASIS_FASTENERS_REVERSE.md (паттерны размещения из GLB).

## Структура zip

```
file.json                  — модель (model + table + modelParams)
models/<имя материала>.obj — 3D-меши фурнитуры (Wavefront OBJ)
models/<имя материала>.mtl — материалы OBJ
```

## Как БАЗИС кодирует фурнитуру с присадками

```jsonc
table.materials[1] = {"name": "Ручка-кнопка, WP0.648.032.0002 Guisti, хром", "art": "3095"}
table.holes = [                       // каталог ТИПОВ отверстий
  {"depth": 16, "diameter": 5,  "drillMode": 1},
  {"depth": 16, "diameter": 10, "drillMode": 1}
]
table.triangles = ["Ручка-кнопка, WP0.648.032.0002 Guisti, хром.obj"]  // ← ИМЯ OBJ в models/
table.objects[25] = {
  "objType": 5,
  "materialIndex": 1,                 // имя+артикул для спецификации
  "triangleData": 0,                  // ← ИНДЕКС в table.triangles (int!), не массив
  "holes": [                          // отверстия, которые ЭТА фурнитура сверлит
    {"pos": {"x":0,"y":0,"z":-16}, "dir": {"x":0,"y":0,"z":-1}, "infoIndex": 1},
    {"pos": {"x":0,"y":0,"z":0},   "dir": {"x":0,"y":0,"z":-1}, "infoIndex": 0}
  ]
}
model.objs += 4 × {"tableIndex": 25, "matrix": [...]}   // ИНСТАНСЫ: один объект,
                                                        // матрица на каждую ручку
```

## Выводы (правила кодирования)

1. **Отверстия принадлежат фурнитуре**, не панелям: pos/dir в ЛОКАЛЬНЫХ
   координатах объекта objType 5; матрица инстанса переводит в мир. Какую
   панель сверлить, БАЗИС определяет сам по пересечению оси с телами.
2. **dir — обязательный вектор направления** сверления (единичный).
3. **drillMode = 1** — обычное сверление; других значений в эталоне нет.
   Сквозное кодируется глубиной: depth = толщине пробиваемой панели
   (у ручки оба отверстия depth 16 при фасаде 16 мм).
4. **Инстансирование**: N одинаковых метизов = 1 объект + N узлов
   `{tableIndex, matrix}` в model.objs. (Реальная тумба: 26 конфирматов —
   ожидаемо 1 объект «Конфирмат» + 26 матриц.)
5. **3D-тело**: `triangleData` — int-индекс в `table.triangles`, где строка =
   имя OBJ-файла в `models/`. Меш можно дать СВОЙ (процедурный цилиндр) —
   формат открытый Wavefront. Материал (name+art) даёт строку спецификации.
6. Панели (objType 2) собственных holes не имеют.

## Что было у нас до AKD-150 (дельта)

| Аспект | Эталон | У нас (до) |
|---|---|---|
| dir вектор | есть | есть (_DRILL_VEC) ✓ |
| triangleData | int-индекс → OBJ | `[]` (пустой массив — расхождение типа) |
| группировка | объект на ТИП фурнитуры + инстансы | один объект «Присадки», мировые pos, матрица 1 |
| 3D-тела метизов | OBJ в models/ | нет |
| материал метиза | name+art (спецификация) | materialIndex 0 (плита!) |

Мировые pos с единичной матрицей математически эквивалентны локальным —
облако принимало наш вариант (round-trip komi_46_HOLES подтверждён). Для
паритета со Studio добавляем: объект на каждый тип метиза со своим
материалом (имя+артикул из BOM), инстансы матрицами, OBJ-тела.

## Открытые вопросы (проверяются платной сборкой, AKD-169)

- принимает ли облако произвольный OBJ в models/ (наши цилиндры) — или
  меш валидируется по каталогу;

  Мебельщик делит на сквозное+торцевое (в эталоне конфирматов нет);
- отображение чашки Ø35 петли (в эталоне нет петель).
