# BASIS production workflow

Рабочая цель: перевести `mebelgen` из генератора визуальных референсов в
контур, который может создавать производственную модель для БАЗИС-Мебельщика и
отдавать технологу `.b3d` с панелями, материалами, кромкой, пазами и фурнитурой.

## 1. Что в БАЗИСе важно для нас

БАЗИС-Мебельщик должен быть конечной производственной средой, а не только
визуализатором. Для производства важны не mesh-объекты, а нативные сущности
БАЗИСа:

- модель `.b3d`;
- мебельные блоки и сборки;
- панели с ориентацией, размерами, материалом и толщиной;
- контуры панелей, включая прямоугольники, дуги, отверстия, вырезы и радиусы;
- кромка на конкретных элементах контура;
- пластик/облицовка пласти;
- пазы и фрезеровки;
- фурнитура, крепеж, отверстия, схемы установки;
- пользовательские свойства, артикулы и имена деталей;
- последующая передача в раскрой, ЧПУ, смету, чертежи и спецификации.

Прямой генерации закрытого формата `.b3d` делать не нужно. Надежный путь:
создавать модель внутри БАЗИСа через его JavaScript API.

## 2. Что уже подтверждено по API

Официальная документация БАЗИС-скриптов описывает JavaScript API для
автоматизации проектирования. В новой документации основные модули такие:

- `objects3d`: создание блоков, панелей и других 3D-объектов;
- `materialData`: создание и назначение материалов и кромки;
- `panelOperations`: кромка, пазы, пластик и операции с панелями;
- `fastenerOperations`: выбор, создание информации и установка фурнитуры;
- `modelIOOperations`: создание, загрузка, сохранение модели, импорт/экспорт mesh;
- `historyOperations`: фиксация изменений в истории построения.

Ключевые функции, которые нам нужны в первом контуре:

- `objects3d.NewBlock(name, owner)`;
- `objects3d.NewPanel(width, height, orientation, owner)`;
- `objects3d.PanelOrientation.front | vertical | horizont`;
- `materialData.SetupActiveMaterial(materialName, thickness, width)`;
- `materialData.SetupActiveButtMaterial(name, thickness, width, isTape, sign, overhung, clipPanel, allowance)`;
- `panelOperations.AddButt(panel, elemIndex, materialData?)`;
- `panelOperations.AddCut(panel, type, name, sign)`;
- `panelOperations.AddPlastic(panel, frontSide, materialData?)`;
- `fastenerOperations.CreateFurnitureInfo(filename)`;
- `fastenerOperations.MountFurniture(info, params)`;
- `modelIOOperations.NewModel()`;
- `modelIOOperations.SaveModelToFile(filename)`;
- `historyOperations.CommitCurrentChanges(name)`.

В старых официальных примерах также есть удобные глобальные обертки:

- `AddFrontPanel(x1, y1, x2, y2, z)`;
- `AddVertPanel(z1, y1, z2, y2, x)`;
- `AddHorizPanel(x1, z1, x2, z2, y)`;
- `BeginBlock(name)` / `EndBlock()`;
- `Panel.AddButt(...)`;
- `Panel.AddCut(...)`;
- `Panel.Build()`;
- `Action.SaveModel(...)`.

Вывод: импортёр лучше писать через маленький адаптер `basisApi`, чтобы один и
тот же JSON можно было прогонять на версии БАЗИСа с новым модульным API или на
старой установке с глобальными функциями.

## 3. Роль JSON

Публичный универсальный JSON-формат модели БАЗИСа не найден. В документации есть
JSON для параметров отдельных операций, например расстановки позиций, но это не
полное описание мебельной модели.

Значит, наш контракт должен быть собственным:

```text
FurnitureSpec JSON        высокий уровень: ТЗ, габариты, цвет, признаки
BasisProductionModel JSON производство: панели, кромки, пазы, фурнитура
Basis import script       читает JSON и строит нативный .b3d
```

Важное правило: `BasisProductionModel` должен описывать производственные
сущности, а не визуальную 3D-сцену.

## 4. Полный процесс от начала до конца

1. Входное ТЗ

   Источник: `.docx`, `.doc`, таблица, текстовая заявка, возможно картинка.
   Уже есть в `mebelgen`: парсинг таблицы, извлечение габаритов, материалов,
   цвета и признаков изделия.

2. `FurnitureSpec`

   Высокоуровневая нормализация:

   - `id`, `title`, `type`;
   - `dimensions.widthMm/depthMm/heightMm`;
   - `materials`;
   - `features`;
   - `parts`;
   - ссылки на исходное ТЗ и изображения.

   Этот слой пригоден для визуализации и предварительного согласования, но
   недостаточен для производства.

3. Конструкторная интерпретация

   Из `FurnitureSpec` выбирается производственный шаблон:

   - шкаф;
   - тумба;
   - тумба с ящиками;
   - стол на боковинах;
   - журнальный стол;
   - нестандартный/ручная доработка.

   Шаблон решает, из каких деталей состоит изделие: боковины, топ, дно, полки,
   фасады, цоколь, задняя стенка, царги, экраны, накладки, вставки, опоры.

4. `BasisProductionModel`

   Генерируется строгий JSON:

   - единицы измерения: только `mm`;
   - материалы с точными именами БАЗИСа;
   - кромочные материалы;
   - блоки/сборки;
   - панели;
   - контуры;
   - кромки по индексам или именованным сторонам;
   - пазы;
   - фурнитура;
   - пользовательские свойства;
   - путь выходного `.b3d`.

5. Валидация вне БАЗИСа

   До запуска БАЗИСа проверяем:

   - все размеры положительные;
   - все материалы существуют в локальном справочнике;
   - каждая кромка ссылается на существующий материал;
   - ориентации панелей допустимы;
   - нет нулевых панелей и отрицательных координат там, где они запрещены;
   - каждая деталь имеет `id`, `name`, `role`, `material`;
   - для каждого архетипа заполнены обязательные детали.

6. Импорт в БАЗИС

   БАЗИС-скрипт:

   - читает JSON через `fs.readFileSync`;
   - делает `JSON.parse`;
   - создает новую модель;
   - создает блоки;
   - создает панели;
   - назначает материалы;
   - применяет контуры, кромки, пазы, пластик;
   - ставит фурнитуру там, где она уже формализована;
   - фиксирует операцию в истории;
   - сохраняет `.b3d`;
   - пишет `import-report.json`.

7. Проверка в БАЗИСе

   Технолог открывает `.b3d` и проверяет:

   - габариты изделия;
   - размеры деталей;
   - материалы и толщины;
   - кромку по сторонам;
   - ориентацию текстуры;
   - пазы/отверстия/фрезеровки;
   - фурнитуру;
   - возможность отправить в раскрой/ЧПУ/смету.

8. Производственный выпуск

   Когда модель принята, дальше работает штатный БАЗИС-контур: чертежи,
   спецификации, раскрой, ЧПУ, смета.

## 5. Черновик `BasisProductionModel`

Минимальная первая версия:

```json
{
  "schemaVersion": "basis-production-model-v1",
  "units": "mm",
  "order": {
    "id": "A-001",
    "title": "Шкаф для документов"
  },
  "output": {
    "b3d": "C:\\Orders\\A-001\\A-001.b3d",
    "report": "C:\\Orders\\A-001\\A-001.import-report.json"
  },
  "materials": {
    "panels": {
      "mdf_25_ral8019": {
        "basisName": "МДФ RAL 8019",
        "thicknessMm": 25,
        "widthMm": 0
      }
    },
    "edges": {
      "edge_ral8019_1mm": {
        "basisName": "Кромка RAL 8019",
        "thicknessMm": 1,
        "widthMm": 25,
        "isTape": true,
        "sign": "RAL8019",
        "overhungMm": 0,
        "clipPanel": true,
        "allowanceMm": 0
      }
    }
  },
  "blocks": [
    {
      "id": "main",
      "name": "Шкаф для документов",
      "panels": [
        {
          "id": "left_side",
          "name": "Боковина левая",
          "role": "side_left",
          "orientation": "vertical",
          "size": { "widthMm": 400, "heightMm": 1800 },
          "position": { "xMm": 0, "yMm": 0, "zMm": 0 },
          "material": "mdf_25_ral8019",
          "edges": [
            { "side": "front", "material": "edge_ral8019_1mm" }
          ],
          "userProperties": {
            "source": "mebelgen",
            "role": "side_left"
          }
        }
      ]
    }
  ]
}
```

На уровне JSON лучше хранить стороны кромки как `front/back/left/right`, а уже
импортёр будет переводить их в индексы элементов контура БАЗИСа. Это уменьшает
число ошибок при генерации.

## 6. Тестовый план

### Test 0: среда БАЗИСа

Цель: понять версию API на рабочей машине.

Скрипт:

- пишет `system.apiVersion`;
- проверяет наличие `objects3d`, `modelIOOperations`, `materialData`;
- проверяет наличие старых глобальных функций `AddPanel`, `AddVertPanel`;
- сохраняет отчет в JSON.

Результат: выбираем реализацию адаптера.

### Test 1: одна панель

Цель: доказать, что скрипт создает `.b3d`.

Действия:

- создать модель;
- создать фронтальную панель 600 x 400;
- назначить материал 16 мм;
- сохранить `.b3d`;
- открыть в БАЗИСе и сверить габариты.

### Test 2: короб шкафа

Цель: проверить координаты и ориентации.

Детали:

- левая боковина;
- правая боковина;
- верх;
- дно;
- задняя стенка;
- две полки.

Проверки:

- общий габарит;
- толщины;
- положение полок;
- имена деталей.

### Test 3: кромка

Цель: проверить перевод `side` -> `elemIndex`.

Действия:

- добавить кромку на переднюю сторону всех видимых деталей;
- открыть карту кромления в БАЗИСе;
- экспортировать/просмотреть спецификацию.

### Test 4: фасады и зазоры

Цель: проверить фасады и правила наложения.

Действия:

- две двери/фасада;
- зазоры по периметру и между фасадами;
- материал фасада отдельно от корпуса.

### Test 5: пазы и задняя стенка

Цель: проверить паз под ХДФ/задник.

Действия:

- добавить паз в боковины/верх/дно;
- проверить траекторию и профиль паза.

### Test 6: фурнитура

Цель: понять, какой уровень автоматизации реалистичен.

Варианты:

- сначала пользователь выбирает фурнитуру через окно БАЗИСа;
- потом фиксируем путь к файлу фурнитуры/закодированные параметры;
- затем импортёр ставит ее автоматически.

Проверки:

- петли;
- push-to-open;
- замок;
- направляющие;
- полкодержатели;
- штанга.

### Test 7: один реальный архетип из `mebelgen`

Первый лучший кандидат: `wardrobe` или `cabinet`.

Причина: это корпусная мебель из плоских панелей, без сложной геометрии.

## 7. Что нужно узнать на установленном БАЗИСе

Эти вещи нельзя надежно закрыть только чтением документации:

- какая версия БАЗИС-Мебельщика стоит у производства;
- какой синтаксис API доступен: новый модульный или старые глобальные функции;
- можно ли запускать БАЗИС со скриптом из командной строки;
- где лежит папка скриптов;
- какие точные имена материалов используются в базе производства;
- как называются/хранятся кромочные материалы;
- как технологи ставят фурнитуру сейчас;
- какие форматы файлов фурнитуры и фрагментов реально используются;
- какие свойства нужны для спецификации, сметы, раскроя и ЧПУ;
- нужно ли создавать отверстия явно или они появляются от фурнитуры;
- какие требования к именованию деталей и артикулов.

## 8. Архитектура в проекте

Предлагаемая структура:

```text
mebelgen/
  basis/
    schema/
      basis-production-model.schema.json
    generate/
      from_furniture_spec.py или .mjs
    validate/
      validate_basis_model.mjs
    scripts/
      import_basis_model.js
      detect_basis_api.js
    samples/
      wardrobe-basic.json
      cabinet-basic.json
    reports/
      ...
```

Для первого этапа достаточно:

- `basis/schema/basis-production-model.schema.json`;
- `basis/samples/wardrobe-basic.json`;
- `basis/scripts/detect_basis_api.js`;
- `basis/scripts/import_basis_model.js`;
- локальный validator в Node.
