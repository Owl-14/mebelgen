# AI orchestration plan

Цель: отделить дорогую/сменяемую нейросеть от детерминированного рендера.

## Текущий режим

Сейчас работаем без внешнего API:

```text
orchestrator/sample-inputs/desk-brief.txt
  -> orchestrator/providers/mock-provider.mjs
  -> demo/three-spike/generated/latest-spec.json
  -> Three.js + SVG technical sheet
```

Команда:

```bash
pnpm pipeline:mock
```

Превью:

```text
http://127.0.0.1:4173/demo/three-spike/
```

## Почему API можно подключить позже

Финальную картинку генерирует не нейросеть, а наш рендерер:

- `Three.js` строит параметрическую 3D-модель;
- SVG-слой строит размеры, стрелки и выноски;
- HTML/CSS собирает лист A4;
- Playwright/headless Chrome позже будет экспортировать PNG/PDF.

AI отвечает за управление:

- разобрать ТЗ;
- вернуть строгий `FurnitureSpec JSON`;
- посмотреть готовый PNG;
- предложить правки, если подписи/размеры/композиция плохие.

## Будущий provider interface

Любая модель должна прятаться за одинаковым интерфейсом:

```ts
extractSpec({ text, files }) -> FurnitureSpec
reviewRender({ image, spec }) -> ReviewResult
```

Первый кандидат на дешевый default-provider: Gemini Flash/Lite-класс или аналогичная бюджетная multimodal-модель.

Дорогую модель держим как fallback:

- ТЗ слишком мутное;
- mock/rules не смогли собрать валидный spec;
- visual review два раза подряд не может исправить лист;
- заказчикский пример сильно отличается от известных шаблонов.

## Что проверяет код без AI

Это должно быть дешево и детерминированно:

- валидность JSON;
- наличие обязательных размеров;
- совпадение размеров на листе со spec;
- выход текста за рамку листа;
- пересечение подписи со штампом;
- наличие обязательных выносок для выбранного архетипа.

AI нужен только для смысловой и визуальной оценки: похоже ли на референс, читаемо ли, не выглядит ли лист кустарно.
