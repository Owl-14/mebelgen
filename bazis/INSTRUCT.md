# INSTRUCT — полная инструкция проекта bazis-json-converter

Документ для AI и разработчика: как из **ТЗ заказчика** получить **готовую модель в БАЗИС**.  
Собрано по итогам разработки (в т.ч. проект «Тумба для модератора» — только как **пример метода**, не как шаблон размеров).

---

## 0. Главное правило: каждое ТЗ — свой расчёт

Главный порядок действий агента зафиксирован в `.cursor/rules/agent-playbook.mdc` (применяется всегда).

**Нельзя** для нового заказа подставлять `placement` из `examples/moderator_cabinet.json` или из `docs/CABINET_DIMENSIONS.md`.

| Что переносится между проектами | Что считается заново по **этому** ТЗ |
|--------------------------------|--------------------------------------|
| Система координат, `basis_orientation` | Габарит W×D×H |
| Правила зазоров (2 мм, z фасадов…) | Число и ширина секций |
| Типы деталей (короб ящика без перемычек) | Высоты ярусов, полок, фасадов |
| Формат JSON, скрипт импорта | Все `placement` каждой панели |
| Логика `carcass_calculation` | Материал, фурнитура, количество ящиков/дверей |

**Порядок для нового ТЗ:**

1. Прочитать чертёж/спецификацию → выписать габариты, T, опоры, секции, фурнитуру.
2. **Просчитать** координаты по формулам (раздел 6) с подстановкой чисел из ТЗ.
3. **Если это тумба/тумбочка** (по словам ТЗ) — обязательно применять `TUMBA_RULES.md` (структура секций, фасадная полоса, зазоры по Z/Y). Для остальных изделий `TUMBA_RULES` не использовать.
3. Заполнить **новый** JSON (`examples/<имя_проекта>.json`).
4. Создать **`docs/<имя_проекта>_DIMENSIONS.md`** — таблицы placement этого изделия (по образцу `CABINET_DIMENSIONS.md`, но со своими цифрами).
5. **Этап 3** — агент сам запускает `python main.py finish examples/<имя>.json` (схема + геометрия + авторазделение полок). См. [AGENTS.md](AGENTS.md), [stages/placement_check/README.md](stages/placement_check/README.md).
6. Импорт в БАЗИС → визуальная сверка с чертежом.

`moderator_cabinet.json` — **один отработанный пример**, не источник размеров для других изделий.

## 1. Цель системы

**Один вход:** чертёж / фото / текст ТЗ заказчика.  
**Один выход:** валидный `project.json` → импорт в БАЗИС-Мебельщик 2026 → модель с панелями и ручками (+ направляющие, когда появится каталог).

```
ТЗ клиента
    → [AI + prompts/system_prompt.txt] → JSON (schema/furniture.schema.json)
    → python main.py validate project.json
    → БАЗИС: basis_scripts/ImportFurnitureFromJSON.js + project.json
    → (позже) каталог: направляющие, петли, раскрой, чертежи
```

**Пример отработанного проекта:** `examples/moderator_cabinet.json` (тумба модератора 1000×400×750) — только для сверки **метода**, не для копирования в другие ТЗ.

## 2. Что уже умеем / что отложено (в целом, без привязки к типу изделия)

| Готово | Отложено (зависит от базы/мастеров БАЗИС) |
|--------|------------------------------------------|
| Панели по `panels[]` (корпуса, полки, перегородки, фасады) | Фурнитура из каталога поставщика (петли, направляющие, замки) |
| Импорт в БАЗИС через `ImportFurnitureFromJSON.js` | Автоматическая кромка/присадка из JSON (потребует доработки скрипта) |
| Ручки через `hardware.handles` (если `count>0`) | Полный «готовый проект» одной кнопкой: отчёты/раскрой/чертежи |

**Важно:** мастера БАЗИС (например «Установка ящиков», «Установка дверей») могут автоматически добавить присадку и механизмы, но это зависит от того, есть ли фурнитура/каталог/настройки в вашей среде.

## 3. История решений (общие ошибки импорта/координат)

| Проблема | Причина | Решение |
|---------|---------|---------|
| Детали «разъехались» | `Rotate*` в скрипте | Только `basis_orientation` + `placement`, без rotation |
| Дно/крышка не той ориентации | Разные правила для полок и дна | Все `horizont`: `NewPanel(spanX, spanZ)` |
| Полки торчат через боковины | Путаница `NewPanel(Z,X)` | Единое правило: horizont = X×Z из placement |
| Стационарные перегородки/лишние детали | Перепутана логика изделия | Для типовых изделий использовать свою базу правил (например `TUMBA_RULES.md`) |
| Щели/пересечения фасадов | Неверный расчёт зазоров | Зазоры считать формулами, не «на глаз»; сверять по `*_DIMENSIONS.md` |
| Ручки в одной точке | Mount1 с локальными координатами | Точка в **ГСК** из `placement` каждого фасада |
| Ручки не создались | Скрипт не нашёл фасады/или `handles.count=0` | В JSON нужны панели `type: door_front`/`drawer_front` + `hardware.handles.count>0`; первый импорт попросит выбрать ручку и запишет `furniture_encoded` |
| Направляющие не в дереве модели | `Mount` между панелями с зазором 16 мм; ручка-кнопка вместо направляющей | `MountBox` / `Mount1` на грани; нужна **настоящая** фурнитура из каталога |
| В параметрическом каталоге нет направляющих | Нет базы поставщика | Пока: пропуск или мастер «Установка ящиков» в БАЗИС |

## 4. Система координат БАЗИС (`basis_mebelshik`)

- **Начало (0,0,0):** левый нижний **передний** угол корпуса.
- **X** — ширина вправо (0…1000).
- **Y** — высота вверх (0…750).
- **Z** — глубина **назад** (0 — перед, 400 — зад).

### Поле `placement` (обязательно для каждой панели)

Габаритный бокс детали в мм:

```json
"placement": { "x1": 0, "x2": 1000, "y1": 38, "y2": 54, "z1": 0, "z2": 400 }
```

- Размер по X = `x2 - x1`, по Y = `y2 - y1`, по Z = `z2 - z1`.
- Скрипт ставит **GabMin** панели в точку `(x1, y1, z1)`.
- **`rotation` всегда 0** — не использовать повороты в JSON.

### Ориентация панели (`basis_orientation`)

| Значение | Детали | `NewPanel` в скрипте | dimensions (width × height) |
|----------|--------|-------------------|-------------------------------|
| `horizont` | Дно, крышка, полки, дно ящика | `(spanX, spanZ)` | X × Z |
| `vertical` | Боковины, перегородки, боковины ящика | `(spanZ, spanY)` | Z × Y |
| `front` | Задняя, фасады, задняя ящика | `(spanX, spanY)` | X × Y |

## 5. Алгоритм расчёта (подставлять значения из ТЗ)

### 5.1. Исходные данные из ТЗ

Обозначения:

- `W, D, H` — габарит корпуса (мм)
- `T` — толщина ЛДСП
- `Hleg` — высота опор (0, если нет)
- `gap` — зазор фасада (`constraints.default_gap`, обычно 2)
- Ширины секций `S1, S2, …` или правило деления из чертежа

### 5.2. Корпус (конструкция `top_bottom_over_sides`)

```
Y_дно_низ  = Hleg
Y_дно_верх = Hleg + T
Y_бок_низ  = Hleg + T
Y_бок_верх = H - T          // низ крышки
Y_крыш_низ = H - T
Y_крыш_верх = H

Дно/крышка:  x1=0, x2=W,  z1=0, z2=D
Боковины:    x1=0 / x2=W-T,  y от Y_бок_низ до Y_бок_верх,  z1=0, z2=D
Задняя:      x1=T, x2=W-T,  y как боковины,  z2=D, z1=D-T (или по ТЗ)
```

### 5.3. Зазоры по Z (фасады впереди)

```
Z_фасад_зад = T          // фасады z1=0, z2=T
Z_полка_перед = T
Z_полка_зад = D - T_зад  // если задняя T
```

### 5.4. Фасады/проёмы по высоте (общая формула для разбиения)

```
Y_фасад_низ = Y_бок_низ + gap
Y_фасад_верх = Y_бок_верх - gap
H_полоса = Y_фасад_верх - Y_фасад_низ
H_одного_фасада = (H_полоса - (N-1)*gap) / N
```

Для каждого яруса `k = 0 … N-1`:

```
y1_k = Y_фасад_низ + k * (H_одного_фасада + gap)
y2_k = y1_k + H_одного_фасада
```

### 5.5. Секции по ширине

Сумма внутренних ширин + всех вертикальных панелей по X = `W`.  
Перегородки: по 1 панели толщиной `T` между секциями — накопить `x` слева направо из чертежа.

**Проверка:** для каждой детали `x2-x1`, `y2-y1`, `z2-z1` должны совпадать с размерами на чертеже (допуск ±1 мм).

### 5.6. Правила конкретных типов изделий

`INSTRUCT.md` не содержит правил «под тумбы»/«под стойки»/«под кашпо». Для каждого класса изделий использовать отдельные базы:

- `TUMBA_RULES.md` — тумбы/тумбочки (ящики/двери/полки).

Если базы для класса нет — считаем изделие «общим корпусом» и строим панели напрямую по чертежу с `placement`.

## 10. Импорт в БАЗИС — файлы и шаги

### 10.1. Файлы проекта

| Файл | Куда |
|------|------|
| `basis_scripts/ImportFurnitureFromJSON.js` | `%USERPROFILE%\Документы\BazisN\Scripts` |
| `basis_scripts/moderator_cabinet.json` (или свой JSON) | любая папка; при импорте указать в диалоге |

Для **каждого** проекта — свой файл, например `examples/client_xxx.json`.  
В `basis_scripts/` копировать **тот JSON, который импортируете**, под любым именем:

```powershell
Copy-Item -Force "examples\<проект>.json" "basis_scripts\<проект>.json"
```

Не перезаписывать чужой проект файлом модератора без явной необходимости.

### 10.2. Порядок в БАЗИС

1. Удалить старые панели (при повторном тесте).
2. **Скрипты** → `ImportFurnitureFromJSON.js` → выбрать JSON.
3. **Ручки:** выбрать в каталоге → **Произвольная → Ручки** или параметрические **Ручки-скобы** → скопировать строку в `hardware.handles.furniture_encoded`.
4. **Направляющие:** пока **Отмена** в диалоге ИЛИ после появления базы — выбрать направляющую → `hardware.drawer_guides.furniture_encoded`.
5. Проверить структуру модели и зазоры на 3D.
6. (Позже) **Установка ящиков** / **Установка дверей** — присадка и направляющие штатно.
7. Материал U 740, кромка → **раскрой**, **деталировка**, **чертежи**.

## 6. Фурнитура в JSON (общая)

```json
"hardware": {
  "handles": {
    "type": "ручка/скоба",
    "size": 128,
    "count": 0,
    "offset_from_top": 32,
    "furniture_encoded": "",
    "furniture_file": ""
  },
  "legs": { "type": "", "adjustable": false, "color": "", "height": 0, "count": 0 }
}
```

- **Ручки:** скрипт ставит их только если `hardware.handles.count > 0` и есть `furniture_encoded` (или выбран при первом импорте).
- **Направляющие/петли/замки:** требуют каталога/базы. До появления базы — ставить мастерами БАЗИС или оставлять как `warnings`.

### Частая ошибка: “верх открыт, а двери на всю высоту”

Если по картинке/ТЗ верхний ярус **открыт** (полка делит корпус), фасады должны закрывать **только нижний проём**:

- дверь `y2` = `y1_полки - gap` (обычно gap=2 мм),
- верхняя зона остаётся без `door_front`.

## 7. Структура JSON (обязательные блоки)

См. `schema/furniture.schema.json`:

- `project_name`, `furniture_type`, `overall_dimensions`, `materials`
- `sections[]` — логические зоны
- `panels[]` — **все** детали с `placement` + `basis_orientation`
- `drawers[]`, `doors[]` — фурнитура и привязка к секциям
- `hardware`, `constraints`, `basis_mapping`
- `warnings[]`, `estimated_values[]`
- `carcass_calculation` — формулы и пояснения (рекомендуется)

Валидация (пример):

```bash
python main.py validate examples/<проект>.json
```

## 10. Чеклист перед импортом (любое изделие)

- [ ] Габариты и T взяты **из этого ТЗ**, не из moderator_cabinet
- [ ] Все `placement` пересчитаны; есть `docs/<проект>_DIMENSIONS.md`
- [ ] `carcass_calculation` содержит **формулы с подставленными числами** этого заказа
- [ ] Правила конкретного класса изделия применены из соответствующей базы (например `TUMBA_RULES.md`)
- [ ] `estimated_values` для всех допущений
- [ ] `python main.py validate examples/<проект>.json` — OK
- [ ] Импорт в БАЗИС, визуальная сверка с чертежом

## 12. Дорожная карта до «один промпт = полный проект»

1. **Кромка и материал** из JSON в скрипт (`panel.Butt`, `MaterialName`).
2. **Петли** — `hardware.hinges` + Mount на дверь/боковину.
3. **Направляющие** — `furniture_encoded` из базы поставщика; опционально `NewBoxesMaker` без дубля короба.
4. **Замки и опоры** — объекты или фурнитура.
5. **Автоконвертер** — INSTRUCT + метод расчёта в system prompt (без копирования чужих placement).
6. **Шаблон отчётов БАЗИС** — раскрой и сборочный чертёж одной кнопкой после импорта.
