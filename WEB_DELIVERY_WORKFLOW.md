# Web delivery workflow

Цель будущего интерфейса: оператор производства получает ТЗ, запускает генерацию,
проверяет лист, при необходимости просит AI внести правку и отправляет результат
клиенту/дизайнеру на согласование.

## Рекомендуемый формат

Основной источник правды: веб-страница проекта.

```text
project/:id
  -> исходное ТЗ
  -> FurnitureSpec JSON
  -> интерактивный лист Constante
  -> история правок
  -> экспорт PDF/PNG
```

Почему так лучше, чем только PDF:

- страницу можно открыть по ссылке и быстро проверить актуальную версию;
- внутри можно оставить кнопки `перегенерировать`, `исправить подписи`,
  `проверить пересечения`, `экспортировать PDF`;
- можно хранить несколько версий листа и понимать, что именно согласовал клиент;
- PDF остаётся фиксированным артефактом для почты, договора и архива.

Практический сценарий:

1. Оператор загружает Word/текст/файлы ТЗ.
2. AI-provider извлекает только структуру: тип изделия, размеры, материалы,
   фурнитуру, примечания.
3. Валидатор проверяет `FurnitureSpec JSON` и реальные материалы из базы.
4. Three.js + SVG renderer строит лист Constante.
5. Автопроверка ищет пустой рендер, обрезание модели, выход текста за рамку,
   пересечение ключевых размерок и выносок.
6. Оператор видит страницу, крутит ракурс в панели, утверждает или просит правку.
7. Для клиента отправляется ссылка на страницу и/или PDF-экспорт конкретной версии.

## Роль нейросети

Нейросеть не рисует финальную картинку. Она управляет пайплайном:

- разбирает грязное ТЗ в строгий JSON;
- выбирает архетип и scene preset;
- сверяет материал с производственной базой;
- смотрит PNG/PDF после рендера и возвращает список правок;
- при двух неудачных дешёвых попытках передаёт задачу fallback-модели.

Первый бюджетный provider: Gemini Flash/Lite-класс или аналогичная мультимодальная
модель. Дорогая модель нужна только как fallback для мутных ТЗ и визуального QA.

## Что уже заложено в прототип

- Рендер не зависит от Codex-чата: это обычная локальная web-страница.
- `FurnitureSpec JSON` отделяет AI от рендера.
- Лист брендирован как Constante.
- Рендерер показывает ошибку прямо на листе, если Three.js/WebGL падает.
- Камера подгоняется по реальному bounding box модели, чтобы не резать верх/края.
- Выноски раскладываются по левому/правому полю и не дублируются в 3D-виде,
  если информация уже дана на фронтальном виде.
